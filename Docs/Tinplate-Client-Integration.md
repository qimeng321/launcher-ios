# 小铁皮苹果客户端接入说明（B150）

## 当前基线
- 工程：qimeng321/launcher-ios
- 分支：tinplate-b150-integration
- 基线 Build：150
- 最低系统：iOS/iPadOS 16.0
- 服务端：用户提供的 Tinplate Server 源码包
- 保留：Ruffle、ZIP/SROM 本地导入、游戏通信、触控/键盘、画质与帧率设置
- 移除：资源服务器 URL、远程资源清单、缺失资源远程补齐和资源热更新代码

## 当前客户端已接入
- 小铁皮服务端地址设置（正式账号通信要求 HTTPS；仅允许 localhost HTTP 开发）
- 普通用户注册和登录
- Keychain 保存会话令牌
- 注册恢复码提示
- 设备随机 UUID 登记
- 公开游戏库读取
- 每个游戏独立保存本地自定义 IPv4:端口
- 读取后台默认连接并应用到现有游戏通信模块

## 服务端接口来源
以随服务端源码提供的 FRONTEND-HANDOFF.md 与 API-NOTES.md 为准。客户端使用 /api/v1/，不调用旧 EML API。

## 当前限制
- 现有游戏通信桥仅支持 IPv4:端口；服务端返回域名或 IPv6 时客户端不会擅自转换，会提示手动设置。
- B150 原有游戏资源目录仍为单个本地安装目录；当前阶段实现游戏库选择和逐游戏连接地址保存，尚未完成多套大体积资源包并存管理。
- 在线补丁列表、Ed25519 公钥固定、补丁依赖解析与多补丁覆盖层尚未接入；不得将“已接入账号/游戏库”描述成完整在线补丁功能。
- 诊断授权、自动日志上传、工单、通知和适配申请界面尚未接入。
- 当前环境没有 macOS/Xcode，代码提交后需要由 GitHub Actions 的 macOS runner 完成真实 iOS 构建；语法解析不等于 IPA 构建或真机验证。

## 安全约束
- 不把管理员会话、补丁签名私钥放进 IPA。
- 账号密码和 Bearer token 仅经 HTTPS 发送。
- 设备 ID 为应用生成的随机 UUID，不读取 UDID。
- 未经用户授权不上传诊断日志。
- 未完成公钥固定前不得启用远程补丁安装。


## Build 151 UI 更新
- 登录、注册和密码找回已改为普通账号密码至少 6 位；服务端对应 API 也需部署本次配套源码更新。
- 新增白色/蓝色登录页、游戏库首页、公告、通知、工单与个人中心入口。
- 游戏内 GameView、Ruffle、B150 游戏通信和本地资源导入内核保持原样；本次没有合入 Air 2 专项优化分支。


## Build 152 固定服务端地址
- 小铁皮 API 地址固定为 `http://1.13.195.4`，客户端首次启动自动使用，不再显示可编辑服务端地址输入框。
- 游戏服务器 IP/端口仍从游戏库读取，并保留用户按游戏单独设置的入口。
- 本构建按开发测试要求使用 HTTP；账号密码、恢复码与 Bearer 令牌在传输中不加密，仅适合受控测试环境。


## Build 153：工单诊断授权
- 新建工单表单新增默认关闭的「授权提交诊断信息」开关；授权仅对当前工单有效，不持久化。
- 未勾选时，工单请求只包含用户填写的问题内容，不读取或发送诊断日志。
- 勾选后先生成脱敏预览；只有用户点击「确认并提交」才会把诊断摘要附加到工单现有 description 字段。
- 预览取消会关闭本次授权并返回表单，不发送诊断摘要。
- 摘要包括客户端/Ruffle 版本、设备类型、iOS/iPadOS 版本、当前游戏和最近相关运行日志；常见凭据、Bearer Token、恢复码、查询参数及本地路径会在客户端侧脱敏。
- 当前仓库未包含 Tinplate 服务端源码或附件上传 API 契约，因此本次以现有 POST /api/v1/tickets 的 description 字段承载诊断摘要；这不是独立文件附件上传，也不能据此宣称服务端已提供附件存储/诊断文件下载能力。


## B154 多游戏与工单文件
- 每个稳定游戏 ID 独立资源、暂存目录、安装备份、增量更新日志、移动补丁覆盖；旧版共享 Game 目录不擅自归属或删除，切换游戏后分别导入原始资源包。
- 导入调用 GET /api/v1/resources/recognize 获取最新规则的特征选择器，客户端提取 SHA-256/XML 特征和路径，再 POST 识别；匹配游戏不符或规则冲突时阻止安装、保留旧资源。适配器已发布且存在时 GET /api/v1/adapters/{id} 获取 SWF 入口及资源路径映射。
- 解压保留 CRC 校验、安全路径检查及解压大小限制，取消 B150 专属的 assets/index.js、WASM、doorConfig.xml 强制条件。游戏运行继续使用 B150 Ruffle 和已有通信桥；新协议、任意适配器参数不保证可运行，需真机联调。运行 WebView 不持久保存游戏缓存和 Cookie，避免跨游戏混用。
- 工单列表、详情、状态、更新时间、管理员回复和补充回复。创建/回复均可上传最多五个文件、额外一个完整诊断 TXT；单文件最大 5 MiB，单次全部附件 12 MiB。
- 诊断授权仅本次有效，默认关闭；用户预览后确认才提交完整当前 diagnostics.txt（保留所有非敏感日志行，不截断成摘要），独立文件附件。系统其他应用的日志不自动访问，用户可手动选取 IPS/TXT。
- 必须部署 B154 服务端配套版本和 Prisma 数据库迁移，才能使用新的识别规则 GET、工单附件与下载。HTTP 仅用于受控测试。


## B156：可选按需缺失资源回源
只在本地补丁覆盖层和底包均不存在资源时，才使用适配器 config.connectionParameters.resourceBaseURL 回源。connectionParameters.builtinDoorConfig 设置为字符串 true 时，远程 config/doorConfig.xml 不可用后才提供 Windows 微端内置默认配置。ServerR.xml 和 ServerOfficial.xml 回源后按当前游戏登录 IPv4:端口改写 endpoint。ip.txt 仍由客户端生成。

未配置源站时不进行远程请求。只允许游戏资源路径；不携带 Cookie/Authorization；最终 URL 必须同源；单文件上限 80 MiB；缓存按游戏/资源/适配器版本隔离。更新适配器后需重新导入资源包。
