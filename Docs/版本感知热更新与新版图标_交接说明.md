# 启动器：资源版本检查、更新与新图标（源码交接）

## 当前实现

- 首页名称：**启动器**。已删除首页“正式版 1.11”角标。安装到 iPhone / iPad 后的图标名称 `CFBundleDisplayName` 和 `CFBundleName` 也是 **启动器**。
- 首页图标 `LauncherArt.imageset/LauncherArt.png` 和系统安装图标 `AppIcon.appiconset/*` 均由用户提供的蓝色门与箭头图片直接缩放生成（没有重新设计）。原图保存在 `Docs/启动器图标_用户原图.jpeg`。
- iOS 内部版本元数据保持不可见，但必须保留，设置为 `1.11.1 (Build 148)`。保持旧版的 Bundle ID `cn.shiguanghao.launcher.m22908`，以便原版本覆盖升级保留数据；该标识只用于系统内部，不会显示为应用名称。
- 首页可以修改**游戏服 IPv4:端口**（默认 `202.189.23.85:22973`）和**资源服 HTTP(S) URL**（默认空）。保存后在下次进入游戏时生效。
- 在资源服已设置、底包已验证时，自动检查版本；首页可手动点击“检查更新”，会显示状态。检查或安装期间不能进入游戏。
- 首先尝试从资源服 `/_overlay/manifest.json`、`/manifest.json` 获取**远程**版本清单。只有清单提供版本、路径和正确的 SHA-256，才能覆盖底包的既有旧文件。若没有可识别的远程清单，则只按需补齐游戏请求但底包不存在的资源；**绝不猜测旧文件已过期**。
- 支持 `.sg_base_version`、`.sg_base_meta.json`、`base.version` 的本地底包版本读取，缺失时退回已识别到的 `SGCore` 修订号；处理 `requireBase`、`baseVersion` 的兼容要求。检查失败不会删除或修改底包。
- 已校验的增量资源存入独立目录；全部文件下载、尺寸（如提供）及 SHA-256 校验成功后，才一次性原子启用新版；上一个版本保留供回退。每次新游戏会话读取已启用版本快照，避免运行中部分文件从旧版跳到新版。
- 当已校验清单证明原始底包中的文件就是正确版本时，会优先使用底包原件而不是较旧的手机补丁；若有校验通过的远程新文件，则优先使用它。
- 不同资源服和底包修订号分隔缓存，缺失资源的按需缓存还会按生效版本分隔。资源服设置界面支持清空缓存。
- 对 `.swf` 检查签名（`version.swf` 允许 KP/PVM 格式），每个资源限 80 MiB；单次全量差分下载不超过 3 GiB；远程清单限 4 MiB、最多 20,000 条。拒绝路径穿越和跨资源服跳转。
- 配置的服务器可能使用 HTTP 明文，因此 `Info.plist` 添加了 `NSAllowsArbitraryLoads`，用于允许用户设置动态 HTTP 资源服。正式部署尽量改用 HTTPS，以免内容或清单被篡改。

## Windows 2.2.0 / 2.3.0 参考的限制

通过安装程序静态分析，Windows 客户端具备 `resBaseUrl`、`loginHost`、`loginPort`、`gamePortBase`、`.sg_base_version`、`.sg_base_meta.json`、`/_overlay/manifest.json`、`requireBase`、`baseVersion`、`basePackName`、`baseHint`、`overlayFiles` 等信息。

**不能从这些字符串断定 Windows 实际使用了哪个远程版本接口，也不能确认远端一定提供 `/_overlay/manifest.json`。** 本 iOS 实现只是支持一种可验证的远程 JSON 清单格式，远端尚需按真实接口调整。

### 可支持的远端清单示例

在资源服根目录添加 `_overlay/manifest.json`（或 `manifest.json`），例：

```json
{
  "version": "2026112401",
  "requireBase": true,
  "baseVersion": "2026111703",
  "basePackName": "完整底包",
  "overlayFiles": [
    {
      "path": "dll/SGCore.swf",
      "size": 3277296,
      "sha256": "<这里填真实文件的64位十六进制SHA-256>"
    }
  ]
}
```

以上版本号、文件大小**仅为格式示例，不能直接发布**；哈希必须是对应资源文件的真实 SHA-256，不可填占位文字。下载地址按`资源服 URL + 文件相对路径`拼接。清单既可用 `overlayFiles`，也可用 `files`；没有哈希的文件仅作为提示，不允许覆盖已有底包文件。版本号不是用大小比较，而是通过清单哈希、已激活版本及校验后的文件判断是否需要更新。

## 构建与验证

这是**源码交付包，不包含新 IPA**。没有 macOS/Xcode 工具链，无法在当前环境完成真正的 iOS 编译、签名或真实服务器测试。请在 macOS 的 Xcode 16+ 打开 `ShiguangLauncher.xcodeproj`，优先用 iPhone 真机测试。

自动化测试：

- `python3 Tests/VersionAware/check_artifact_sources.py`：检查桌面显示名、图标、工程目标和网络权限。
- `swiftc -frontend -parse Sources/*.swift`：Swift 源码语法解析。
- `swiftc Sources/RuntimeServerSettings.swift Sources/ResourceHotUpdater.swift Sources/ResourceVersionManifest.swift Sources/ResourceVersionUpdater.swift Tests/VersionAware/ManifestTests.swift -o /tmp/test-manifest && /tmp/test-manifest`：清单解析、路径校验和本地底包版本。
- `python3 Tests/VersionAware/run_http_integration.py`：启动**本机模拟资源服务器**，验证下载、SHA-256、原子启用和不重复下载；不访问真正的资源服。测试缓存放在独立临时目录，不会删除实际用户资源。
- `.github/workflows/ruffle-b142-gpu-memory-fix.yml` 已改为使用源码附带的 `第三方依赖备份/Ruffle_B142_已验证构建产物.zip`，不依赖已经删除的旧 GitHub 仓库 Actions 构建产物。工作流的 Rust/Ruffle 引擎仍是 B142 经过验证的构建。

## 待真机验证

1. 安装后 App 名称“启动器”、图标及首页图标；无首页版本号。
2. 首次导入完整底包；游戏服登录和 20 个频道代理正常。
3. 资源服未配置或不可达：原底包能离线进入游戏，缺文件仍按原逻辑处理。
4. 远端存在兼容版本清单且提供 SHA-256：自动发现并下载变更；第二次检查不重复下载。
5. `requireBase` 与本地版本不匹配：跳过更新、底包不受影响。
6. 中途断网、哈希错误、资源服务器更换：旧版本仍可使用，新文件不发生半成品替换。
7. 修复版手机补丁与新版 `SGCore.swf` 的覆盖优先级，以及礼包、命运之轮、NoNo 的实际功能。

**重要**：取消首页显示的版本号，不等于删除 iOS 系统要求的内部版本元数据；否则可能无法可靠升级或安装。
